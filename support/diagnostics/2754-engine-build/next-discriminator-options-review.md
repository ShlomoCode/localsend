# Source-only discriminator options review

Scope: independent assessment only. No code changes, symbol fetching, VM/UI activity, workloads, builds, tests, or runs. Stock-debug acquisition/qualification belongs to the other helper.

## Recommendation

Qualify official exact-Build-ID debug information first, before VM/UI work. Then propose **one bounded client birth-to-root-Name transport capture, followed by a stopped-state snapshot after verified tracer detachment**, rather than repeat the current post-entry-only capture or introduce a Name-entry breakpoint first. Keep the existing unmodified geometry client, public call sequence, 180-second external deadline, strict geometry validator, package controls, and modal-close/parser failures. This would be diagnostic evidence only; its timings cannot certify normal latency or geometry success.

The smallest useful trace observes the unmodified client from exec/birth through its root GetName entry and a bounded follow-up window. It records connection establishment/FD identity and syscall bytes; it adds no client barrier, D-Bus call, property mutation, or artificial reply. Trace both directions of the client's private connection. Initially avoid tracing all app threads: complete client send/receive traffic can establish whether a root Name reply reached the client, while a later app snapshot can retain callback state. This is materially smaller than tracing the whole app from launch.

This is a reviewable proposal, not authorization to implement or run it. Launcher integration must preserve process ownership and the existing deadline. A daemonized strace launch mode is a candidate because it can leave the geometry client as the invoking launcher's child; its exact installed-version behavior must be resolved from documentation/source before using it. Do not casually insert `timeout strace client` and reuse the old direct-child/PID cleanup assumptions. Tracer termination must demonstrably detach the client and leave its original 180-second lifetime in force. Retain actual tracer identity, all live-task TracerPid checks, and independently verified exit before GDB.

## What verified stock debug can and cannot provide

Exact symbols are necessary for correct DWARF locations, private types, source-line attribution and instruction mapping. They **do not guarantee recoverable locals at an optimized suspended frame**. A variable can be optimized out, unavailable outside its location-list range, represented only by a reused register, or have no valid lifetime yet. A debugger cannot restore such values simply because symbols match. Never infer a value from the ABI register of an old frame unless exact instructions and unwind/location information establish its current meaning; never assume argument registers survived the intervening dispatch calls.

Both observed dbind depths must be audited separately. Record frame/thread/depth/PC, exact loaded library Build ID and function offset, source and disassembly around the call/return path, and all variable availability states. The outer `_atspi_dbus_get_property` and `atspi_accessible_get_name` frames plus geometry `walk(depth=0)` establish API context. They do not identify an arbitrary nested dbind message as Name. The inner `atspi_state_set_contains` frame is a different query and could use the same or another connection.

Source anchor: `atspi-misc.c:1368–1400` constructs a `Properties.Get` message for `aobj->app->bus_name` and `aobj->path`, then appends the interface and property name and invokes dbind with `aobj->app->bus`. Require complete header **and body** bytes to prove `org.a11y.atspi.Accessible` and `Name`; the header's Properties/Get alone is insufficient. At a public `atspi_accessible_get_name` entry stop, this message may not exist yet, and the API may satisfy a cache path. At dbind entry the message can exist but its serial can still be zero before libdbus assigns a serial on send.

Source anchor: `dbind.c:63–126` contains two distinct branches. The different-unique-name branch assigns `ret` from send_with_reply_and_block and then may drain dispatch. The null/same-destination branch uses pending-call closure and read_write_dispatch until closure->reply. A source line shared across instructions or the exported function name cannot prove a specific branch or that assignment has completed. Require exact PC/instruction mapping; for the normal branch require a valid initialized returned message, including error replies, not just a non-null-looking local. For the closure branch read actual closure/pending state if available, and do not apply the normal branch's ret-before-drain inference.

The prior equal dbind PCs at both depths plus nested dispatch are compatible with a private connection/null unique-name candidate. They do not establish it. Official debug may resolve this; if local locations still fail, retain unknown.

## Non-inferior memory navigation

Typed stopped-memory reads can inspect a recovered DBusConnection, its transport, the socket FD, message header/body buffers, and possibly pending calls and incoming/outgoing queues. The existing root-name-gdb.py already uses exact `DBusMessage`, `DBusRealString`, and `DBusTransportSocket` types, avoiding inferior calls. These are appropriate mechanisms when the exact debug types actually contain the fields and readable objects.

However, this source review has no local exact libdbus 1.14.10 source tree, so it cannot certify the names/layouts of its connection hash tables, list links, pending-call members or platform mutex/condition wrappers. Qualification should inspect that exact source and debug type inventory before proposing traversal. A shared library's debug package can omit or lack usable private types even when its Build ID matches. Fail closed rather than guess offsets or cast every transport as a socket without checking its runtime class/vtable against exact source.

If supported by exact types, a bounded traversal may read pending-call records and message queues without calling helpers: retain node addresses, membership, serials, header/body bytes and parse status. Bound node count and bytes, track visited pointers, and flag unreadable/invalid links. Never call dbus_message_get_*, dbus_connection_get_unix_fd, hash iterators, mutex helpers, GLib functions or AT-SPI getters in the inferior. A stopped process can have an object mid-update; shape plausibility alone is insufficient.

A message recovered from pending state/queues is a candidate until linked to the current wait connection and exact Name serial. Queues can already have consumed or removed messages; empty queues or absent pending entries are not proof of no earlier reply. Current connection/application pointers can help correlate, but cannot replace the suspended call's actual connection without a justified relationship.

The current collector targets dbind/property/callback frames but does not target the unknown libdbus frames or explicit dbus_connection_dispatch/wait frames. A later proposal should consider typed reads from those frames where DWARF exposes their `connection` argument, then map the observed condition-wait object to that connection's exact dispatch synchronization member. If both connections are recovered, compare their pointers explicitly. A condition address by itself does not identify an owner or prove deadlock; all relevant thread stacks and ownership fields must support that claim. Do not infer that two dispatch frames use the same connection merely from their function names.

## Compare the options

| Option | Main benefit | Main weakness | Suitable conclusion |
|---|---|---|---|
| Stock-symbol post-entry stopped snapshot | Can resolve branches, types, held messages and actual wait connection without earlier breakpoint | Optimized locals may remain absent; consumed historical traffic is unrecoverable | Snapshot state, branch/connection correlation if proven; prior traffic unknown |
| Client birth-to-Name bounded syscall trace + later snapshot | Captures request serial, reply_serial and FD lifecycle before the current observation gap; can work despite optimized locals | Scheduling perturbation; finite window; split/coalesced/syscall payload limits; decoder and lifecycle integration required | Positive wire request/reply facts within complete captured byte ranges, plus snapshot wait linkage |
| Public Name-entry GDB stop | O0 fixture caller identity may be robust; exact argument context retained before call | Pauses before message/serial exist, changes event ordering, misses later wire outcome unless continuing with more stops/trace | Entry identity only; insufficient as the sole Name discriminator |
| Property/dbind-entry or send/return breakpoints | May capture argument/message at a known lifetime and recover branch progression | More stop/resume perturbation; nested/cached calls; serial not assigned at early stop; optimized location issues remain | Stronger staged data only with exact PCs and explicit perturbation controls; larger proposal |

The birth trace is preferred because the failed run's precise gap is historical: both clients were already nested in dispatch before attach and had no captured syscall IO afterwards. A public Name-entry breakpoint would stop earlier but cannot alone close the serial/reply gap. Keep an untraced control of the same accepted workload for behavior comparison; existing untraced observations may serve if their package/UI/fixture provenance is identical. Do not promote tracing-influenced timing to a regression/performance claim. If the phenomenon disappears under tracing, report that limitation rather than widen the workload blindly.

## Fail-closed evidence gates for any later proposal

1. Official debug qualification: exact runtime ELF hashes/Build IDs; trusted stock package identity/version; matching debug Build IDs; necessary source/disassembly/type visibility; no replacement/rebuilt runtime libraries. Failure stops before VM/UI activity.
2. Provenance and lifecycle: unchanged accepted app package/loader/fixture; exact trace/filter/limits/tool version; unique app/client/tracer PID+starttime; FD open/connect/dup/close lineage including FD reuse; guaranteed 180-second deadline; bounded collection; actual detach and cleanup proven for retained identities.
3. Wire identity: decode complete root path, Properties.Get header, body Accessible/Name, nonzero request serial, direction and actual socket. Reassemble split/coalesced D-Bus messages with byte-order/alignment/body lengths. Mark partial/truncated/lost spans; don't infer from printable Name text.
4. Reply evidence: match reply_serial to the Name request on the same connection, record return or error type and direction. Bytes read by the client prove kernel-to-client delivery, not that the Name wrapper has consumed/returned it. Missing reply in a finite or gapped window stays unknown.
5. Wait evidence: exact per-depth PC/branch, recoverable message/pending/closure state, connection pointer→validated transport FD→recorded socket, relevant libdbus wait/dispatch frames. An optimized-out component remains unknown rather than reconstructed by assumption.
6. Causal claims: “reply before dispatch drain” additionally requires exact normal-branch PC after completed assignment and the initialized matching reply. Closure-loop observations require their own interpretation. Neither a idle app snapshot nor successful observer status proves callback/reply history.
7. Product outcome: strict geometry validation and the original 180-second outcome remain separately reported. Modal-close obstacle and validator parser failure are not bypassed or reclassified as successes by a diagnostic Name finding.

Only proceed with a concrete source proposal after gate 1 qualification results show which private type/PC paths actually exist. If those cannot support stopped wait linkage, the birth trace may still recover valuable positive wire facts, but the combined causal result must remain partial.
