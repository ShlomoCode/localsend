# Observe Finder handover in the official macOS app

This source-only diagnostic qualifies one hosted `macos-15` arm64 desktop and observes the official LocalSend 1.18.2 DMG installed at `/Applications/LocalSend.app`. The reporter used an M1 with Sequoia 15.7.3. Shared readiness evidence from trial 3441 recorded M1 Virtual hardware with macOS 15.7.9. This run records its own actual hardware and point release; matching major release and architecture does not establish an exact reporter-environment match.

The workflow runs only in `ShlomoCode/localsend`, with one job and a 35-minute limit. It requires an existing unlocked console desktop, native accessibility permission, and screen-capture permission. The helper enables the supported native `AXEnhancedUserInterface` attribute to expose Flutter accessibility semantics. It records the setter return independently and requires enabled readback, because trial 3441 observed enabled readback despite return `-25208`. It does not alter TCC, app preferences, or the signed bundle, or replace app code. A missing permission stops qualification and preserves evidence.

The experiment performs these steps:

1. Record the runner, console session, operating system, architecture, and display hardware.
2. Download the official 1.18.2 DMG over HTTPS, with a bounded SOCKS5 fallback only for HTTP 418. Record headers and assert SHA-256 `126860d56f6f49b11845f601aac51de27a49b16d2b48102415da91e0e37e5155`, corroborated by trial 3441 and retained run 38205824955. Assert its historical 52,700,247-byte asset size, verify signatures and Gatekeeper assessment, and retain the app plist and executable architecture. Compare the installed executable with the mounted original. Require a fresh native preferences domain and no portable settings file.
3. Open LocalSend normally. Select **Send**, choose **File**, navigate the native file picker to `2897-control.txt`, and choose **Open**. Require **Files: 1**, select **Edit**, and require the exact filename on the selected-files page, supported by its native accessibility tree, screenshots, and a continuous video.
4. Quit LocalSend and require process absence. Reveal and select `2897-cold.txt` in Finder. Invoke its native context menu, choose **Open With**, and choose **LocalSend**. Observe the opened app, then inspect **Send** for the named staged file.
5. Quit, launch LocalSend without a filename, select **Send**, verify the empty picker branch, and record the running process. Repeat the same Finder operation for `2897-warm.txt` and require the process ID to stay unchanged.
6. Verify the signed installation again, retain logs and original recordings, terminate the diagnostic app, detach the DMG, and remove only the installation that this run created.

`ax.swift` traverses native accessibility children, visible children, selected children, and windows. It deduplicates elements, restricts actions to enabled targets that advertise the native action, and rejects ambiguous labels. Finder files can expose **AXShowMenu**. If the selected named Finder item lacks that action, the helper right-clicks the center of its native accessibility bounds. It requires one selected element and a frontmost Finder process. The helper records the chosen action and coordinates. It never substitutes `open -a LocalSend FILE` for the Finder menu.

Startup qualification first records an app-owned on-screen native window and process, then enables semantics before checking app labels. **Send** and **Receive** actions match the qualified native labels `Send\nTab 2 of 3` and `Receive\nTab 1 of 3`. Local-network permission handling is limited to the native `com.apple.UserNotificationCenter` process, the exact prompt `Allow "LocalSend" to find devices on local networks?`, one enabled **Allow** button, and one enabled **Don't Allow** button in the same window, sheet, or dialog. It records the prompt tree, screenshot, and action result, and rejects ambiguous controls.

Each observation retains native trees, screenshots, subprocess statuses, and unified logs. Native `screencapture` records the real display continuously until the final case screenshot, with a 240-second hard cap. The harness requires the recorder to remain alive at that screenshot, retains a three-second tail, and sends SIGINT to finalize the movie within a bounded 15-second wait. It records the native exit status; a forced stop fails qualification. The case timeline records capture-command start, action start, and final screenshot times. AVFoundation requires a playable track whose duration covers the recorded capture-start-to-final interval, and exports three frames for inspection. The complete original video stays unchanged. Review the recording, especially the Finder submenu choice and the app result, before interpreting the ledger. A short presentation clip can be derived later without replacing the retained original.

`result.txt` distinguishes infrastructure failures, candidate reported failures, and observed control/handover success. The Send selection card renders a count and thumbnail, so filename absence there is not a failure. Success requires **Files: 1**, **Edit**, and the exact expected filename on the selected-files page. A candidate failure requires the strictly empty Send branch: **File** is present, **Edit** is absent, and no selection count is present, after the picker control and Finder operation succeeded and LocalSend opened. A wrong count, stale file, unexpected selection, or unavailable Edit-page filename fails qualification as infrastructure. A successful job is an observation packet, not proof of reproduction. One cold and one warm case do not establish repeatability or causality. The bookmark hypothesis remains unproven.

Subcommand filenames use only ASCII letters, numbers, underscores, periods, and hyphens. Each `.command-label.txt` retains the original label, including punctuation from visible UI labels. The workflow always archives the complete raw evidence directory as `evidence/issue2897.tar.gz` and uploads that safe outer filename. On failure, the exit trap prints the stage, script exit, last failed subcommand and status, and at most 6000 bytes from each of its stdout and stderr streams before cleanup. The last failed subcommand is diagnostic history; a tolerated failure need not be the cause of the script exit.
