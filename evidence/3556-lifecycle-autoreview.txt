[P2] P2: Account for ignored starts before using stopSelfResult
support/cloud_transport/android/RelayService.java:89
After readiness is observed, the mode buttons are enabled again, so another tap can deliver a newer start ID while `running` is true. `onStartCommand` ignores that request without updating `ownedStartId`. If the pull or accept worker subsequently fails, `stopSelfResult(ownedStartId)` returns false because Android has received a newer start request. Unlike the previous `stopSelf()`, this leaves the failed foreground service alive, with cleanup never invoked and listeners potentially still bound. Track the latest delivered start ID even for ignored requests, or otherwise ensure failure stops the current owned service instance.

overall: patch is incorrect (0.98)
The lifecycle observation improvements introduce a failure-cleanup regression: an ignored subsequent start request prevents the owned worker from stopping its service after a failure.
