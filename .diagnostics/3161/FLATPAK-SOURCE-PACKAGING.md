# Supported Flatpak source packaging proposal

The retained official manifest at flathub commit `e6a71e097895` uses freedesktop Platform/SDK25.08 and installs a complete LocalSend release TAR through ordinary flatpak-builder build commands. Source-built complete control/B TARs can enter through this same declared archive input, with their accepted archive hashes. This changes the declared source/build inputs rather than replacing an engine after packaging.

Before a candidate is accepted, retain the exact full Flathub commit, its shared-modules gitlink, the source/archive manifest and metadata inputs, the engine/framework/app manifests, and the flatpak-builder version and full build log. Verify installed runtime commit `d27f7a6a974e40b061070bec1be9e1b52a7a6872b271e6a45c2c34a48bf6fedf` against the original evidence before use. SDK commit is `0cc82216a407cc993941b5ddabd446becc3c9a6219d9bcf50125c60101dcad46`. A 25.08 branch name alone does not pin the reported 25.08.17 runtime.

The draft AT-SPI module builds exact 2.54 source through Meson into flatpak-builder's normal `/app` prefix. It must precede LocalSend. Use stock and A source variants with identical SDK/build options and all other modules unchanged. Apply A to source through a declared patch input and retain the exact production diff and native test gate. The retained discriminator's `--exclude=tests/*` build did not execute those native tests in this SDK; that limitation must remain explicit until the supported package test prerequisites are available. No post-build copy of bridge binaries is part of this proposal.

This route still requires testing: `/app/lib` must resolve the intended complete ATK/bridge dependencies through the ordinary Flatpak launch environment. Compare declared normal loader paths with the original package, retain `/proc/PID/root`-relative ELF hashes and namespace PID identities, and fail if the runtime's `/usr` bridge loads in place of the selected source module. The native bundle verifier deliberately rejects loader injection and is not a Flatpak namespace verifier.

Normal flatpak-builder stripping and debug splitting may change a complete ELF hash. The proposed `verify-packaged-bundle.sh` keeps both source and packaged hashes, requires every accepted bundle file, compares ordinary assets exactly, and compares ELF allocated bytes, load layout and GNU Build ID. It preserves readelf output and objcopy binary comparisons. It rejects unsupported ELF encodings and missing Build IDs rather than weakening a comparison. This source-only helper needs independent review and a successful cloud execution before its runtime result is accepted. The actual running namespace must then match the packaged all50-file hashes exactly; source equivalence does not substitute for that loaded-artifact gate.

The declared `dest-filename: at-spi2-core-254.tar.gz` corrects inference without changing source bytes or their hash. Live rounds now require successful preparation. This is an infrastructure repair, not a new reproduction result.

Use independently installed build refs and fresh equivalent external app profiles. Preserve the unmodified historical 1.17 package alongside source diagnostics; a source c1ce Flatpak remains a different app version. The useful controlled source matrix is control-engine/stock-bridge, B-engine/stock-bridge, control-engine/A-bridge, and B-engine/A-bridge. Execute sequentially within the one-job-per-bug budget, keeping the real GNOME Zoom, tab, geometry, speech, edit/action and lifecycle assertions. Do not call A or A+B a complete fix until all relevant cases and the reported packaging workflow pass.
