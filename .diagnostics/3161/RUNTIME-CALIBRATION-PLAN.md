# Runtime acceptance plan for issue 3161

This is a source preparation plan. No runtime oracle or new source-package UI result is accepted. Root decides acceptance after reviewing the actual evidence.

1. Retain the exact installed GNOME Shell, Mutter, GTK, pyatspi and AT-SPI package versions, Debian source package identities and distribution patches. Retain DisplayConfig `GetCurrentState`, monitor modes/scales, the selected configuration, the compositor snapshot and observed Shell theme scale. Upstream48.7 source establishes only the proposed formula until the installed distribution's implementation is checked.
2. Use the working native GTK Calculator and a standard GNOME Text Editor field as controls. Select real controls with physical pointer/keyboard input and retain their actual rendered text/caret in continuous video. Keep the window at an observed nonzero origin. Use a supported display configuration with observed Shell theme scale greater than1; record configuration before/after, never substitute text scaling or a screenshot ratio. If the environment cannot expose that scale, this calibration requirement remains unmet.
3. Capture Component WINDOW and SCREEN observations separately, real caret WINDOW extents, focused source and retained ACTIVE frame/dialog/window ancestor. Correlate each event's observed time interval with repeated compositor snapshots, the actually focused window and independent rendered control/caret. Apply only the reviewed consumer formula: client-content origin plus observed Shell theme scale multiplied by WINDOW extents. Internal agreement among accessible methods is insufficient.
   Move the same window between two independently observed nonzero positions while keeping the focused child's layout fixed. Require the predicted target delta to match the rendered control/caret delta. Retain actual magnifier follow-focus, follow-caret, mouse tracking, magnification and tracking modes before/after; enabled alone does not establish the consumer configuration.
4. Match the actual compositor credential/XRes host PID to `/proc/PID/stat` starttime, executable, namespace `NSpid`, Flatpak instance and actual loaded maps. Accessible provider identity must be mapped to that exact instance. The proposed Python collector explicitly lacks durable bus/object identity, so its name/PID/ancestry observations alone cannot pass provider mapping. Retain supported AT-SPI bus event/connection evidence or mark this requirement unresolved; do not use private fields or title/PID2 inference.
5. Focus another working app. The LocalSend `--require-focused` compositor gate must reject that state, and the raw collector must preserve the other app's events. Regain LocalSend focus and verify the same exact instance and ancestor. Settled snapshots cannot substitute for event-time correlation.
6. Perform the identical real focus/edit/tab sequence with the collector stopped, then running. Preserve action timestamps, video/audio, actual text changes and latency. Slow, capped, timed-out or identity-unresolved collector observations remain inconclusive. A collector query completion is not a UI success or proof of absence of perturbation.
7. After this once-per-unchanged-environment positive calibration, retain original1.17 Flatpak baseline and run the four normal source packages separately with fresh equivalent profiles: control-stock, control-A, B-stock, B-A. Native Wayland is primary; Xwayland is an explicitly labeled control with separately verified backend/identity. Require all package, installed namespace, geometry, physical tab/edit, speech and lifecycle gates on the process used for each actual scenario.

The actual Zoom viewport must follow the rendered focused control/caret in raw video. A missing parent, all−1 extents, inaccessible source, failed identity gate, warning suppression alone or unchanged viewport after a real focus/caret move does not pass. Observed SCREEN zero coordinates may be a toolkit limitation; GNOME's WINDOW consumer path remains the normative geometry contract.
